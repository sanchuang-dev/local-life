# 居民联系资料与认证身份

2026-11-24 维护者裁决，取代 #257 和 #258 中将认证手机号作为联系电话唯一来源的旧约定；#93 的 OTP 认证契约不变。

- 居民 UUID 仍是平台主键。微信和经 OTP 验证的手机号是认证身份；`resident_phone_identities` 只证明身份，不再作为运营联系电话。
- `resident_profiles.contact_phone` 与 `contact_address` 是居民自填的联系资料。手机号仅做大陆手机号码格式校验，允许为空、修改、清除及多个居民填写同一个号码。无需短信，不自动绑定、换绑或合并账号。
- H5「我的资料」直接填写并统一保存联系电话和地址。PATCH 使用居民本人会话与 CSRF/Origin 验证；兼容旧客户端仅提交地址时保留电话。
- 用户管理详情管理员可读完整联系电话和地址，其他授权社区人员仅见脱敏联系电话；认证身份脱敏号是独立字段，不得当作联系号码。订单核验沿用原服务端授权边界，从居民资料读取联系方式。
- 0041 迁移一次性将历史已验证号码复制为联系号码，保留原运营联系方式；此后两个字段独立演进，清除联系号码不回退到认证号码。
- 不接短信服务商，不改微信登录、手机号 OTP、社区归属、支付或奖励行为。
- 本地 Chrome QA：微信外拦截页提供「开发模式入口」，保留当前地址并启用当前会话的 UI 预览；随后使用现有开发居民登录。仅 Vite DEV 构建可见，API 仍要求非生产且显式启用 AUTH_DEV_ENABLED，正式环境不支持绕过。
