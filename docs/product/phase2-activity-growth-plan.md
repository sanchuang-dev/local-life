# 本地生活二期｜银发社区活动裂变试运营方案（V2.0）

> 状态：**产品讨论收敛稿，待负责人评审；非施工授权、非对外发布承诺**  
> 日期：2026-10-20  
> 归属：sanchuang-dev/local-life；二期产品范围的单一方案文档  
> 目标：2026 年 10 月底争取启动一场**真实、可核验、可兑现**的银发社区活动试运营。  
> 依据：2026-10-20 产品脑爆、仓库 dev 分支 AGENTS.md / design.md / README.md，以及现有社区页、活动详情与社区样例数据。未有广电实际接口、奖品报价、商户合同或真实后台接入证据。

## 1. 为什么做、做成什么

### 1.1 已确认的现实边界

- **可依托的资源**：广电团队的用户触达、线下推广人员与硬件商品渠道；本地商户商品、服务体验券及魔镜等可纳入供给讨论，但具体合作与库存未获证实。
- **不依赖的资源**：街道办业务在二期不作为交付前提；不假设街道、公职服务背书。
- **重要传闻**：广电可能有机顶盒/用户终端识别和电视端触达能力，**未核实**；设备标识不等于家庭真实身份或住户画像。二期不以这些能力为启动条件。
- **现有技术事实**：local-life 的 dev 分支仍是 React + TS + Vite + Tailwind + React Router + Lucide 的演示站。社区活动详情已存在，报名/扫码签到/支付/账号/奖品兑现仍是 Mock 或提示，并非可运营业务。dev Pages 预览不是生产系统。

### 1.2 产品定位

**以活动聚集用户，以三人开团带动传播，以实物及本地权益促进参与，以广电/本地商户/魔镜销售形成商业转化。**

面向居民的关键词：**三人成团、天天有奖、社区争榜、活动冲大奖**。

二期不是再造泛本地生活商城；活动可以完成线下报名、签到、咨询、成交与核销，不以在线支付为前提。

### 1.3 本期目标和非目标

**本期试运营目标**：能真实创建活动、分享邀请、确认参加及签到、组成三人团、登记线下有效成交、核发可兑现的权益、统计社区和推广人员结果、结算活动成本。

**非目标**：完整商城及支付/库存/配送系统、政府公共服务、医疗健康画像、复杂团队层级和多级分佣、九人团/战队系统、强制微信小程序化、电视端识别与定向广告接口、全自动网格员分账。

## 2. 面向用户的核心玩法

| 玩法 | 用户可感知的机制 | 试运营边界 |
| --- | --- | --- |
| 三人开团 | 三位真实参与者组成一团，达成活动定义的签到或消费条件，解锁团队奖励 | 固定三人；不搞九人团、跨层级计奖 |
| 活动阶梯奖励 | 同场活动达到公开的阶段目标，逐档解锁鸡蛋、纸巾、商户体验等权益 | 档位有限、数量有限、不可无限循环返本 |
| 每日抽奖 | 有效参与者每天可获得一次抽奖资格，从公开的五档奖池中按规则抽取 | 不以额外付费购买抽奖机会；库存、概率、时间、规则透明 |
| 社区排行 | 按活动内已核验成果汇总社区排名，展示社区成就与奖项 | 优先统计有效参与/成团；不展示住户隐私 |
| 活动大奖 | 活动结束前宣传大奖，前 N 名领奖或前 N 名取得开奖资格 | 这两种兑奖口径尚未二选一，不能先在界面承诺 |

### 2.1 三人团

- **三人团是玩法单元，邀请关系是传播证据**。二者需要分开记录，不能用一条邀请链直接等同一支队伍。
- 一个团只有 **3 位独立有效参与者**。团长/发起人是否占这三席、如何组队与如何锁团，仍属于必须定稿的产品决策。**原型候选方案**：团长占一席、再邀请两位成员；待负责人确认后才成为实现合同。
- 同一活动一个用户最多被计为一个有效团成员。活动之间允许重新组队；历史仍按活动保存。邀请归属遵循本活动首次有效确认，不因再次打开邀请链接改变。
- 团队奖励是一份共同权益，不默认每名成员都发一份。具体是由队长领取、三人抽签，还是兑换成其他权益，属于**每场活动的可选规则**，需在开团前展示并在达标后留痕。
- **签到团**：三人完成经核验的签到，解锁小礼物（鸡蛋、纸巾等）。
- **消费团**：三位成员产生规则允许的有效成交，团队累计到达公开门槛，解锁约定的实物或本地商户权益。购买可在线下完成、由授权运营人员录入并经核验。退款/取消须撤销尚未兑现的成绩与奖励资格；已兑现异常走人工争议处理。
- 对「消费总额 3，返参考价值 1」的理解：**是营销权益的展示参考比例，绝不是现金返佣、保证返本、利润率或预算公式**。用户展示价值必须可证实，绝不虚构原价。

### 2.2 阶梯及奖池

- 阶梯示意：达到一档，开放对应实物/权益；后续档位可以升级奖品，但数量、资格、成本和发放次数必须预设上限。
- 奖池允许：生活耗材、真实可兑换的本地商户手艺/生活体验券、零售优惠券、广电硬件相关福利、魔镜展示设备/体验资格等。
- 对外展示时区分**参考价值、兑换条件、有效期、数量**；内部登记采购成本、补贴来源、预计兑付率、物流/核销费、实际核销成本。
- 参与者不应凭纯分享点击直接算有效新客；推荐人和被邀请人都要清楚知道活动条件。严禁多级付费推广资格和按下级销售额返奖。

### 2.3 抽奖及排行榜细则

- 每日抽奖：建议按活动所在时区自然日计算，已有效报名且满足公开条件者每日最多一次；奖品设五档，由单场活动配置数量及概率。没有条件及奖品供给确认前不公布虚构中奖率。
- 社区排行：试运营建议默认**有效签到人数**，并同时提供有效三人团数、经核验成交额的运营分析；最终指标及并列规则待定，不允许临时改评奖口径。
- 活动大奖：区分 **按排名直接发奖** 与 **排名前 N 名取得抽奖资格** 两种明确玩法，运营选其一。界面不能混用「前 N 名必得」与「前 N 名中随机抽出」。
- 避免用户误以为每日参与、指定消费能保证抽到大奖。所有随机奖项需可审计的开奖记录、清晰规则和人工复核通道。

## 3. 参与流程与页面

### 3.1 用户旅程（以一场真实活动为例）

1. **看到活动**：广电网格员线下分享、现有社区入口、活动链接/二维码进入活动详情。
2. **参与确认**：理解活动时间、地点、规则、奖品、数据用途；完成最低限度实名去重/联系方式确认（具体认证方式待技术与合规评审），确认是否接受邀请。
3. **三人组队**：展示空位、有效成员、目标进度和可拿到的奖品；可以转发邀请。
4. **有效行为**：授权工作人员记录签到；购买商品可在线下成交后登记凭据，由运营核验后计入本团。
5. **即时反馈**：达标时出现清晰的「组队成功」与奖品待领取/待审核/已发放状态，不能将待审核假装成已到账。
6. **持续回访**：每日抽奖、活动阶梯、社区榜及大奖倒计时；无需每次重新组队。
7. **兑现与结算**：用户出示核销码或现场领物，工作人员核验；完成记录对账与活动复盘。

### 3.2 最小页面清单（不重画整站）

**居民侧**
- 活动详情：主题、场地/时间、活动规则、主 CTA、奖品展示、参与条件、开奖说明。
- 我的三人团：3 席成员、当前签到/有效成交进度、分享邀请、有效/待核验状态。
- 我的奖励：待达成/待审核/待领取/已核销/已失效，以及二维码或兑换说明。
- 活动榜单与抽奖入口：活动有效期、公开资格、奖池和结果；可为活动详情内的区块而非多个一级页面。

**工作人员 / 运营侧（可先用极简后台）**
- 活动发布/上下线与规则冻结；奖品及预算配置。
- 工作人员现场签到、人工审核成交、退款/撤销与异常处理。
- 奖品发放、核销与库存/剩余预算；可导出最小对账记录。
- 按活动/社区/推广人员的成果汇总（权限隔离、只展示必要信息）。

**既有导航约束**：以 dev 现有「首页 / 社区 / 健康 / 惠生活 / 我的」为基线，不在本方案中擅自改一级 Tab。活动应首先从「社区」现有活动入口进入，并可在首页放推荐位。继续沿用 design.md 的清爽绿色、移动端友好视觉；活动详情可适度增强进度反馈、喜庆动效和开奖仪式感，不能牺牲银发可读性和操作简洁度。

## 4. 规则和数据最小合同（概念级，不是数据库 DDL）

- **Activity**：活动 ID、时区、开始结束时间、状态、举办方、参与条件、公开规则版本、可选能力开关、社区范围。
- **Participation**：活动 ID、用户 ID、来源渠道、参与状态、去重状态、确认及时间戳；同一用户同一活动唯一。
- **InvitationEdge**：活动 ID、邀请人、被邀请人、接受状态、来源、确认时间；同活动只认一个有效邀请归属，历史不跨活动继承。
- **Team / TeamMember**：活动 ID、团队 ID、成员 ID、团长、席位、成团/锁团状态；同一参与者本活动仅计入一个有效团。
- **CheckIn**：参与人、活动、场次、核验方式、操作员、时间、撤销原因；唯一有效签到，不允许刷新重复计算。
- **SaleEvidence**：成交凭据索引、参与人/团队、商品供给方、有效金额、审核状态、退款回滚、操作员；购买必须可追踪但不强制在本站收款。
- **RewardRule / RewardGrant / Redemption**：奖池、档位/中奖条件、数量、兑付预算、归属主体、发放和核销状态、过期与撤销轨迹。
- **Draw / Result**：规则版本、资格清单快照、开奖结果、奖品数量及审计流水；前 N 名规则和每日抽奖分别记录。
- **CommunityAttribution / PromoterAttribution**：活动的社区 ID、推广渠道/网格员来源；**用户社交邀请归属 ≠ 网格员销售分账归属**。
- **AuditLog**：审批、改规则、改库存、补登签到、补登销售、手工发奖/撤销等不可静默覆盖的记录。

原则：一份事实只存一个权威来源；同一业务操作要有幂等键。原始个人信息最小化采集；跨活动保留传播历史需要明确告知与合法处理依据；公开排名只输出社区统计，不输出个人家庭画像。广电的设备标识和收视信息禁止在未核实授权前接入。

## 5. 实际运营与钱的口径

### 5.1 奖励成本的真账

一场活动至少设置：总奖品数量上限、总活动预算上限、奖品库存、每档最大发放次数和核销有效期。展示参考价值不参与利润核算。

**实际活动净贡献（概念）＝已核验商品销售毛利/商户补贴/可确认收入 − 赠品实际成本 − 兑奖履约成本 − 渠道与推广结算 − 活动运营成本 − 退款/争议损失。**

不能把「卖 300 送标价 100、采购花 25」直接称作盈利，因为商品成本、履约和渠道分成尚未扣除。活动预算达到阈值时停止新增奖励资格，已承诺奖励仍须履约。

### 5.2 广电、网格员、商户

- **商户**：明确商品和体验券的真实兑付内容、供给价、核销限制、售后主体。
- **广电**：明确哪些是渠道触达、哪些是实际销售，合同里的对账方式和分账口径待谈。
- **网格员**：保留来源推广 ID、现场核验人与有效成果；具体薪酬/佣金比例及结算主体待商定，不能用用户邀请树直接等同网格员分佣树。
- **平台**：掌握活动规则、可审计成绩与兑现状态；无合同和可核验成本时，不上线「推三返一」的高价值设备奖承诺。

## 6. 月底真实试运营：做减法后的交付建议

### P0：没有这些，就不能叫真实试运营

1. **一场活动可真实发布**：真实日期、地点、规则、合作方和参与条件；链接可被分享。
2. **可去重的参与和邀请关系**：用户能加入，邀请来源按活动稳定记录；不能仅存在浏览器本地。
3. **真实三人团与签到核验**：团成员唯一、工作人员可确认/撤销、进度反映真实状态。
4. **最小奖励兑现**：一类现货小礼品或已签约券能按规则发放、核销、做库存预算对账。
5. **最小运营台账**：能查活动、人员来源、签到、成团、奖励与失败/纠纷情况；有操作权限。
6. **可恢复的业务环境**：持久化服务与部署、备份/导出、异常反馈、移动端实际端到端走查。静态 GitHub Pages 演示不算完成上述条件。

### P1：二期完整活动营销能力，按依赖增量上线

- 活动内阶梯奖励、社区榜单。
- 每日五档抽奖及开奖结果。
- 活动前 N 名大奖。
- 本地商户券、广电硬件、魔镜销售的线下凭据核验和高价值奖品核发。
- 网格员归因报表与后续正式分账。

**优先级解释**：P1 是已讨论的二期玩法，但是否都能在 10 月 31 日真实兑现，取决于活动/奖品、合规、工作人员及持久化服务是否就位；可以先把界面做成真实规则展示，不得把虚拟开奖或模拟发奖伪装成正式运营。

### 建议倒排，不构成开发承诺

- **10/20–10/22：业务拍板**。确定第一场活动、三人团归属、签到核验方式、最小用户认证、奖品真供给、预算上限、合作商户/网格员现场负责人。
- **10/23–10/27：P0 联调**。最小后台与活动页、邀请/签到/发奖闭环，使用真实持久化记录，线下核验可用。
- **10/28–10/30：封闭试运营与演练**。小范围实际人员试用、模拟取消/退款/重复扫码/作弊、盘点礼品库存、上线前告知规则及客服联系方式。
- **10/31：是否试运营**。基于真实证据决定启动或缩减范围，不以页面预览或 CI 绿灯替代业务验收。

## 7. 必须明确的待决事项（避免研发自行猜）

1. **团成员定义**：团长是否属于三人；成员能否退出/换团；成团后是否锁定。建议试点：团长占一席、同活动一人一团、成员未签到前允许经审核替换。
2. **签到计算**：三人线下签到是否必须同场次；是否可跨天；是否允许工作人员代办及现场核验依据。
3. **消费门槛**：金额按含税实付还是订单标价；跨商家是否累加；退款如何回退；「三人都购买」是否必需。建议试点明确三名成员分别有有效购买记录，按净实付汇总。
4. **团队奖归属**：团长领取、全团任选一人还是团内随机抽；每档能领取几次。建议活动创建时固定，不允许达标后临时改。
5. **阶梯指标与榜单**：个人/团队累计、签到/成交哪个为主；大奖前 N 名究竟直接得奖还是取得抽奖资格。
6. **身份与渠道**：能否用手机号或微信授权识别有效人，老人无智能手机如何由现场工作人员协助；合作广电能否实际投电视入口。
7. **首场奖池与预算**：哪几件商品/券真能供给、用户感知价值/真实成本/可核销时限和奖品数量；广电/网格员实际结算权责。
8. **合规与客服**：促销奖励、概率公示、虚假标价、多级计酬、个人信息处理及争议处理均需在上线前核查。不能凭一份脑爆稿认定合法。

## 8. P0 业务验收口径（验收的是结果）

- **真实报名**：两台不同设备分别登录后参加同场活动，刷新/重新进入仍看到一致状态；同账号重复报名不增人数。
- **邀请归属**：B 接受 A 的本场邀请并加入后，改点 C 的链接不覆盖归属；在另一场活动可重新建立关系。
- **三人成团与签到**：三名有效参与者形成一团；未签到不冒充签到；重复二维码/重复操作不重复增加进度；工作人员撤销后状态回退并有审计证据。
- **奖励兑现**：三人签到达标只创建约定数量的团队奖，库存按实占用；待领、已领、撤销状态可追踪，重复核销失败；预算超限时不误承诺新奖。
- **线下销售**：只有经授权确认的凭据可计入消费；退款后成绩与尚未兑付资格撤回，已兑付产生争议清单，不私自删交易记录。
